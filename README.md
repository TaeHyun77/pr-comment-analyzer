AI를 활용한 PR 리뷰 코멘트 분석을 자동화하여 코드 리뷰 과정의 반복 작업을 줄이는 시스템입니다. 분석 결과 재사용을 통한 LLM 호출 및 토큰 사용량 감소와 정확한 분석에 중점을 두었습니다.

PR에 코멘트가 달리면, AI가 해당 코멘트를 분석하여 요약, 현재 방식과 제안 방식의 비교, 판정, 근거, 답변 초안을 생성하고 이를 Slack으로 전송하여 리뷰 코멘트의 핵심 내용을 빠르게 파악할 수 있도록 합니다.<br><br>

### PR COMMENT 분석 과정
---
1. 웹훅 수신 : GitHub 웹훅 이벤트 수신
   
2. 비동기 분석 실행
   
3. 코드 체크아웃 : PR의 head 커밋을 임시 폴더에 체크아웃
   
4. Claude 프로세스 실행 : `claude -p`로 별도 프로세스 생성
    - 읽기 전용 도구 (`Read`, `Grep`, `Glob`)만 허용
    - 개인 설정, 플러그인, MCP 차단
    - 세션 기록 비활성화
    - 시스템 프롬프트로 분석 지시 전달
      
5. 코드 분석 : Claude가 직접 파일을 탐색하고 분석한 뒤 JSON 결과 반환
   
6. 결과 처리 : JSON 파싱 및 DB 저장
    
7. 임시 파일 정리 : 체크아웃한 임시 폴더 삭제
    
8. Slack 알림 : 분석 결과 전송<br><br>

### 구현
---
- PR 코멘트 리뷰 분석 파이프라인 구축
    
    GitHub 웹훅으로 PR 리뷰 코멘트를 수신하고, Claude Code CLI를 활용한 비동기 분석 및 결과 저장 파이프라인을 구축했습니다.
    
- 코드 변경 맥락을 반영한 리뷰 분석
    
    파일 diff와 PR 설명을 함께 전달하여 코드 변경 내역과 작성자의 의도를 파악하고, 실제 코드를 탐색하여 리뷰 지적의 타당성을 검증하도록 했습니다.
    
- 분석이 불필요한 코멘트 처리
    
    단순한 감사, 동의, 확인 등의 코멘트는 불필요한 분석 비용을 발생시키므로, 이를 줄이기 위해 LLM이 분석 전 필요성을 판단하고, 질문이나 새로운 주장이 없는 단순 답글은 분석을 생략하도록 했습니다. 
    
    판단이 애매한 경우에는 분석하며, 생략 결과도 DB에 저장하고 Slack으로 사유를 전달합니다.
    
- 대댓글 간 대화 맥락 처리
    
    대댓글은 이전 대화의 맥락에 따라 의미가 달라질 수 있습니다. 이를 고려하여 대댓글 분석 시 해당 스레드의 부모 댓글과 이전 대댓글을 시간순으로 함께 전달함으로써 대화 흐름을 분석에 반영하도록 했습니다.<br><br>
    

### 트러블슈팅
---
- 리뷰 단위 묶음 분석으로 LLM 중복 탐색 제거
    
    [ 상황 및 문제 ]
    
    기존에는 코멘트마다 별도의 Claude 프로세스를 실행하여 분석하면서 동일한 코드 탐색과 분석이 반복되고 토큰 사용량이 증가했습니다.
    
    GitHub는 여러 코멘트를 하나의 리뷰로 묶어 제출할 수 있습니다. 이를 활용하면 리뷰 단위로 코멘트를 모아 한 번에 분석할 수 있다고 생각했습니다..
    
    [ 해결 ]
    
    여러 코멘트를 리뷰 단위로 묶어 분석을 한 번만 실행하도록 개선했습니다.
    
    GitHub의 `Start a review`와 `Submit review`를 활용하여 하나의 리뷰에 포함된 코멘트를 모아 분석합니다. 
    
    라인 코멘트 3개와 총평 1개를 기준으로 비교한 결과, LLM 실행 횟수는 4회에서 1회로 줄었고 비용은 51%, 토큰은 53% 감소했습니다. 
    
    하지만, 병렬 분석이 사라지기에 전체 분석 시간은 약 32초에서 51초로 증가하여 트레이드오프가 있지만, 반복적인 코드 탐색을 줄여 분석 비용을 절감할 수 있었습니다.
