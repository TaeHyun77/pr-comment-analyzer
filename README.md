① PR 생성 시, AI가 언어 → 프레임워크/인프라 → 도메인/보안 → 최종 검증의 단계로 코드를 분석하고, 분석 결과를 해당 PR에 코멘트로 게시합니다.

② 특정 PR에 코멘트가 달리면, AI가 해당 코멘트를 분석하여 요약, 현재 방식과 제안 방식의 비교, 판정, 근거, 답변 초안을 생성하고 이를 Slack으로 전송하여 해당 코멘트에 대해 사용자가 빨리 파악할 수 있도록 합니다.<br><br>

1. 웹훅 검증 및 분석 대상 확인

   GitHub에서 코멘트 웹훅이 전달되면 서명을 검증하고, 다음 6단계의 필터링을 거쳐 분석 대상을 확인합니다.

   - `X-Hub-Signature-256`을 직접 계산해 대조하여 GitHub에서 보낸 요청인지 검증
   - 새로 작성된 코멘트인지 확인 ( 수정/삭제 이벤트는 분석하지 않기 때문 )
   - 분석 대상 저장소인지 확인
   - 분석 대상으로 설정된 코멘트 유형인지 확인
   - 내 PR에 작성된 코멘트이며, 작성자가 봇이 아닌지 확인
   - 실제 분석할 내용이 있는지 확인 ( 빈 총평 등은 분석하지 않음 )
     
2. 분석 작업 등록 및 즉시 응답

   필터링을 통과한 코멘트에서 분석에 필요한 정보만 추려 분석 작업으로 등록하고, GitHub에는 즉시 `200 OK`를 반환합니다. GitHub는 웹훅 요청에 대해 빠른 응답을 기대하므로, 실제 분석은 별도의 스레드에서 비동기로 처리합니다.
    
3. 중복 처리 방지 및 분석 데이터 수집

   DB 락을 획득하여 동일한 코멘트에 대한 중복 분석을 방지하고, 이미 처리된 결과가 있다면 분석을 종료합니다.

   이후 PR의 최신 커밋을 확정한 뒤, 해당 커밋을 기준으로 코멘트 문맥, 파일 변경 내역, 코멘트가 작성된 파일의 본문을 수집합니다. 파일은 크기 제한을 고려해 필요한 범위만 잘라 분석에 사용합니다.
    
4. AI 분석 수행

   수집한 정보를 하나의 프롬프트로 구성하고, AI에게 파일 읽기, 디렉터리 조회, 분석 결과 제출 세 가지 도구를 제공합니다.

   AI가 추가 정보가 필요해 도구 호출을 요청하면 애플리케이션이 GitHub API를 호출해 결과를 전달합니다. 이 과정을 AI가 최종 분석 결과를 제출할 때까지 반복합니다.
    
5. 결과 저장 및 알림

   AI가 제출한 분석 결과를 DB에 저장하고 Slack으로 전송합니다. 이후 작업을 완료 상태로 기록하고 분석 과정에서 생성된 임시 데이터를 정리합니다.
    
6. 예외 처리 및 락 해제

   모든 처리가 완료되면 획득한 DB 락을 해제합니다.

   처리 중 예외가 발생한 경우에도 반드시 락을 해제하며, 완료 상태는 기록하지 않습니다. 따라서 동일한 작업이 이후 다시 처리될 수 있도록 합니다.<br><br>

### PR 분석
---
PR 생성 시, 언어 → 프레임워크/인프라 → 도메인/보안 → 최종 검증의 4단계를 통해 PR을 분석하며, 리뷰어가 코드를 열어보기 전에 아래 항목으로 구조화된 요약을 PR 코멘트로 게시합니다. 

대충 훑고 넘기는 리뷰를 줄이고, 리뷰어가 어디에 시간을 집중해야 할지 미리 가늠할 수 있게 하는 것이 목적입니다.

- 해결하려는 문제가 무엇인지, 왜 해야 하는지
- 어떻게 해결했는지
- 이 PR의 한계 & 트레이드오프
- 기존 기능에 미치는 영향
- Edge Case & 실패 시나리오
- 검토한 대안과 선택 이유
- ⭐️ 리뷰 포인트 : PR 내 파일/영역별로 위험도를 표시해 리뷰어가 어디에 검토 시간을 집중해야 하는지 미리 가늠할 수 있게 합니다.

큰 PR일수록 분석과 리뷰 모두 정확도가 떨어지므로, 분석 대상 파일 수(PR_REVIEW_MAX_FILES)와 파일별 patch 길이(PR_REVIEW_MAX_PATCH_CHARS)를 제한해 과도한 토큰 사용과 응답 지연을 방지합니다.<br><br>
