# 주석 / 문서 작성 컨벤션

## 기본 원칙

- 모든 주석은 한글로 작성한다. (식별자는 영문 - `CLAUDE.md` 응답 규칙 참조)
- What이 아니라 Why를 설명한다. 코드를 그대로 옮기는 주석은 달지 않는다.
- 코드만 봐서는 알 수 없는 것 - 의도, 트레이드오프, 제약, 엣지 케이스, 단위 — 을 남긴다.


## 주석 종류별

### 클래스 주석
- 클래스의 역할/책임을 한두 문장으로 남긴다.
- 여러 줄이면 `/ */` Javadoc, 한 줄이면 `//`.

### 메서드 주석
- 이름과 시그니처로 자명하면 생략한다.
- 비자명한 동작/부수효과/호출 시점 제약만 `//`로 남긴다.

### 필드 / 상수 주석
- 단위, 목적, 근거를 `//` 인라인으로 남긴다.

### 인라인 주석
- 비직관적인 결정의 이유를 짧게. 부연은 `—`(대시)로 잇는다.


## 하지 말 것

- 코드를 그대로 반복하는 주석
- 주석 처리된 죽은 코드 방치 - 필요 없으면 삭제한다.
- 코드와 어긋난 낡은 주석 방치 - 코드 변경 시 주석도 함께 갱신한다.
- TODO/임시 결정은 이유와 해소 조건을 함께 남긴다. (예: `// 확인 후 INFO로 되돌릴 것`)


## 설명 글 / 문서 (PR 설명, 리뷰, 리포트 등)

- 결론(요약)을 먼저, 근거를 뒤에 배치한다.
- 트레이드오프가 있으면 선택한 이유와 함께 제시한다.
- 여러 항목은 중요도순으로 정렬하고, 가장 추천하는 것을 맨 위에 둔다.
