### 현재 브랜치를 main과 비교해 PR 제목/브랜치명을 추천 (필요시 여러 PR로 분리 제안)

브랜치 네이밍/커밋 컨벤션을 `rules/commit.md` 기준으로 삼아줘

1. `git log main..HEAD --oneline` 와 `git diff main...HEAD --stat` 로 이 브랜치가 main 대비 작업한 전체 변경을 파악해줘

2. 먼저 이 변경들이 하나의 응집된 기능/목적으로 묶이는지, 아니면 서로 독립적인 여러 기능이 섞여 있는지 판단해줘

3. 하나로 묶이는 경우 - 단일 PR로 추천 (rules/commit.md 컨벤션 준수)
   - 영어 브랜치명: feat/기능명, fix/버그명 등, 하이픈 구분
   - 한글 PR 제목: `<타입> <한글 설명>` 형식, 50자 이내
   - PR 본문 초안: 무엇을 왜 변경했는지 요약

4. 여러 기능이 섞여 있는 경우 - 큰 틀에서 독립적인 단위로 나눠 각각을 별도 PR로 추천
   - 각 PR마다: 영어 브랜치명 + 한글 PR 제목 + 본문 초안
   - 어떤 파일이 어느 PR에 속하는지 매핑도 함께 제시
   - 단, rules/commit.md의 "커밋 단위" 규칙을 존중해 너무 잘게 쪼개지는 말 것
   - 나눌지 말지 애매하면, 나눈 안과 안 나눈 안을 모두 제시하고 트레이드오프를 짧게 설명해줘

실제 브랜치 생성/push/PR 생성/커밋 재구성은 하지 말고, 추천만 제시해줘
